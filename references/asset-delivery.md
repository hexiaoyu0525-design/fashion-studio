# AI 资产双通道交付与归档（asset-delivery）

> 归属：fashion-studio · 作用域：**fs 全部 AI 生成/编辑产物，无例外**——款式图、效果图、大片、lookbook、面料、平铺、挂拍、细节、工艺、模特/人台、系列图等一切图片产物，以及视频/音频；不限于 Muse/模特资产。
> 前置：建模特与标准资产包走 `ai-model-muse.md`；资产库运营走 `muse-asset-library.md`；版权合规走 `copyright-compliance.md`；素材库字段走 `asset-library-schema.md`。
> 版本：1.3 · 许可 CC BY 4.0

## 一、核心动作（工具中立，任何平台/Agent 通用）

**fs 的每一张 AI 生成或编辑产物，完成"生成"不等于完成——必须同时完成两个动作，缺一不可：**

1. **拿到产物句柄**：生成工具返回的原始短链 / URL / 本地文件（**必须逐字使用工具返回值，不下载、不重传、不换链**）。
2. **持久归档**：把产物写入可跨会话找回的位置——云端画布 / 云盘语义目录 / 本地素材库与项目文件夹。归档目录按语义组织（身份锚点、母版、历史版本、交付物分开）。
3. **可见交付**：把产物**直接展示**给用户（对话框媒体卡片 / 图片预览 / 文件卡片），不是只给路径或文字描述。

> 判定标准：产物未归档 + 未直接展示，= 未交付。缺一个就补一个，不静默跳过。

## 二、豆包办公默认实现（画布写入 + 本地归档 + 对话框展示）

> 豆包办公的实现 = **一条原始产物短链，三端同落**：① design-cli 画布写入（持久化 + 画布展示）→ ② 本地项目文件夹归档（持久存档）→ ③ 对话框媒体卡片展示（可见交付）。三端共用**同一条工具返回值**，不下载、不重传、不换链。换环境见第四节。

### 1. 绑定画布（初始化）
- 当前对话已有唯一有效 `canvas_workspace_id` 时直接复用；没有时调用 `design-cli design-workspace +workspace-create --title "<标题>"` 建一张，从响应 XML 读唯一 ID，并由主 Agent 用 `present_files(<workspace_id>)` 交付画布卡片（**不得**创建 workspace-id.txt 等中间文件）；画布卡片交付成功前不得生成/编辑媒体、不得执行 Item/Frame 写命令。
- `+get-workspace` 只用于显式查询、恢复或排障，不代替"对话无 ID 时必须创建"的初始化规则。
- 命令统一形状：`design-cli design-workspace +<command> [flags]`；domain 与 `+` 都不可省略，漏 `+` 或拼错命令名是退出码 2 的错误。

### 2. 画布写入（持久化分支，Agent 必做）
- 把生成工具返回的原始短链写进画布——`design-cli design-workspace +create-batch --canvas-workspace-id <画布ID> --input -`，stdin 传 XML：

```xml
<batch>
  <items>
    <item type="IMAGE" path="/generated-assets/<语义名>" title="<短名>" brief="<一句话摘要，供判断是否回读>">
      <size width="1672" height="2508" />
      <asset url="<生成工具返回的原始短链>" />
    </item>
  </items>
  <frames></frames>
</batch>
```
- 写入后必须 `design-cli design-workspace +get --canvas-workspace-id <画布ID> --item-ids <返回ID>` 回读，核对 URL/type/path/title/brief 与对象 ID。`title` 是端上给用户的短名、`brief` 是给自己消费的判断字段，两者不要填成一样。
- **判据是返回 `code`（0=成功），不是 HTTP 状态**；退出码 2=参数拼错、1=业务/XML 结构错（重读对应命令页核对后重试）。
- 批量**全成或全败**：单次 XML ≤1MB、单批对象 ≤50（顶层 Item + Frame + 成员合计），超限直接拒、不截断。
- 衍生图在 `<source_ids>`（成员 `<source_id>`）里声明来源 Item/Frame ID——只 `+create` 系生效，服务端用它决定落位，不只是记血缘。
- **交付分支**：主 Agent 将生成工具返回的**同一条原始短链**通过媒体卡片（RichMediaCard）逐项展示；可批量（≤6 张/组）展示，逐项确认。用户"看到图"以此为准，不得只给路径或文字描述代替。

### 3. 本地项目文件夹归档（持久存档分支，默认并行）
- 同一产物**同时**落进当前项目文件夹对应阶段目录（结构见 `project-workflow.md` 第〇节），命名 `季节码_系列_板名或图种_版本_日期`；这是跨会话找回的持久存档，画布只是它的镜像。无画布环境时本节独立承担"持久归档"。

### 4. 语义目录（画布 path 与本地目录对应）
- **画布顶层四类**（path 必须以 `/` 开头，写不存在的 path 自动构成目录，无需 mkdir）：
  - `/user-anchors`（用户上传的原始锚点：模特参考、Logo、品牌图）
  - `/core-assets`（核心资产母版：`/core-assets/<语义名>/master`）
  - `/generated-assets`（可复用生成资产）
  - `/deliverables`（最终交付物）
- **本地对应**沿用 `project-workflow.md` 第〇节：`01_前期企划板/`（灵感/主题/色彩/面料/纹样工艺/廓形/配饰板）、`02_设计效果图/`（效果图/成衣定稿）、`03_款式图/`、`04_配饰版/`、`05_摄影大片/`（参考图/大片/细节特写）、`06_视频/`（分镜/关键帧/成片）、`00_项目画布/`（进度看板/设计宪法/素材日志）；**各阶段目录下含 `定稿版/`**（用户拍板确认的图复制一份，见 `project-workflow.md` 第〇节 8）；`_历史版本_<造型>/`（旧版移入，可回滚）。

### 5. 版本与血缘规则
- 同一身份衍生 N 个变体 = N 次独立生成/编辑调用（每次同一锚点），不用单次多结果代替。
- 内容修改后的新版本 = 新文件 / 画布新 Item（版本号递增），不覆盖旧版；旧版移入本地 `_历史版本_<造型>\` 或画布历史区，可回滚。
- 衍生图用 `<source_ids>` 记录血缘并决定画布落位；`+update` 只改顶层 brief/path，不改内容，不补血缘。

### 6. 已知环境坑（仅豆包办公实测，不属通用方法论）

> 以下为豆包办公环境**实测踩坑记录**，仅供本环境参考；换平台/Agent 时按第四节降级走通用通道，**不要把这些坑当通用规则照搬**。通用方法论（双参考分离、强压词、防漂移等）在 `ai-model-muse.md`，本节点到即止。

- **"背面全身 + 贴身连体/吊带"组合单独生成易被内容审核拦截**（`output review not pass`）→ 降级通道：从三视图合成图裁剪对应视角板块（按实际合成版面取对应视角板块），已验证可行。

## 三、Muse 人物资产包（引用，不重复）

Muse/固定模特的标准资产包（6 件母版、配套身份卡与总览索引、换装=全套重出）定义见 `ai-model-muse.md` 第三节与五·5，本文件不重复；**建好即按第一、二节双通道闭环交付**。非 Muse 的普通出图同样执行第一、二、四节，必须双通道闭环。

## 四、其他环境降级（工具中立）

- **无 design-cli / 无画布环境**：跳过画布写入，归档落在本地项目文件夹或云盘语义目录（`项目/资产/模特/Muse-XX/`），交付用平台的图片/文件展示能力。
- 核心动作不变：句柄 → 归档 → 可见交付。只是"画布"换成"文件夹/云盘"。
- 换 Agent / 平台时按 `tool-adapter.md` 做能力映射。
