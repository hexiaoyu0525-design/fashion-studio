# 时尚官网/秀场素材自动采集

把"给一个网站或品牌名"变成"归档一批可用的参考素材"：自动打开官网、定位最新季秀场/系列页、提取设计理念文字、下载高清图，并按素材库规范落盘登记。

## 触发条件

- 用户给出品牌官网 URL、秀场 URL、或品牌站名，要求收集图片/参考图/秀场图、读取设计理念、保存素材。
- 典型任务："去 LV 官网找最新一季秀场，存两张图给我并说说设计理念"、"把某品牌 2027 春夏的秀场图抓下来做灵感板"。
- **纯文字描述也可触发**：用户没 URL、没图，只有文字（如"某品牌 2027 春夏主打轻纱层叠+柔光+莫兰迪色"、"帮我整理新中式盘扣在现代秀场的用法"）→ 不走抓取，直接把文字整理成**设计调研要点**落盘（来源=用户提供/Agent 整理，权限 ⚪ 知识或 🟢 主题概念），同样进调研板/灵感板/素材库。

## 零门槛说明（不熟悉技术的人先看这里）

**完全不需要理解下面的技术**：最简方式是手动放图或直接把参考图发到对话/项目文件夹，fashion-studio 会扫描登记并继续。本 skill 的浏览器自动化通道只服务「想批量收集 / 想自动抓取」的用户；用不用、用哪条，都不影响手动放图这条**永远可用、人人可用**的路。

## 执行引擎（三通道，按环境选择——不是自动降级）

浏览器采集有 **三条可选通道**，由当前环境与任务规模决定走哪条；不熟悉技术的人**直接选通道③即可，零门槛**：

| 通道 | 实现 | 适用场景 | 代价 |
|---|---|---|---|
| ① 本地 playwright-cli | `npx --package @playwright/cli playwright-cli` 命令式操作 | 批量、定时、需本地网络/代理、无人值守 | 需本地 Node.js ≥ 18 + Chrome（或 Playwright 内核），首次配置 |
| ② Agent 内置浏览器自动化 | Agent 自带的浏览器驱动（如内置 bu / computer_use_tool） | 临时少量、零部署、实时判断、登录可接管 | 批量多次往返、速度慢；出口网络受后端环境限制（如国际站可能被 WAF 拦） |
| ③ 手动放图 / 直接发参考图 | 用户下载/截图放文件夹，或直接把图发到对话/项目文件夹 | **最简方式、零门槛，人人可用、永远可用** | 慢，但不需要环境与任何理解成本 |

**选择逻辑**：不熟悉技术 / 只想给参考 → ③（零门槛）；想自动化：批量/定时/要本地网络 → ①；临时少量/零部署 → ②。

**纯文字输入（不依赖任何通道）**：只有文字描述、没有 URL/图时，无需抓取——Agent 直接把描述整理成**设计调研要点**落盘（见「落盘规范」文字类），属于 ⚪ 知识或 🟢 主题概念素材。

- 通道①命令细节见开源 `openai/skills/playwright` 的 SKILL.md；Windows 用 pwsh 执行。
- 不要改用 MCP 服务器（豆包 Work 环境不支持 MCP）；不要自行编写并维护长脚本，优先命令式组合。

## 新环境初始化（换机 / 新电脑首次使用）

本技能可移植：**内核装不上 ≠ 功能不可用**。换新电脑后按下面顺序，不必先装任何东西：

1. **优先零安装**：通道②（Agent 内置浏览器，客户端自带）或通道③（手动放图）——任何机器、任何网络都可用，日常任务走这两条即可。
2. **需要本地批量/定时/无人值守**（才需要通道①）：Windows 跑 `assets/setup.ps1`（macOS/Linux 按脚本内注释手工执行）——一条命令完成：检查 Node/npx → 验证 `@playwright/cli` → 冒烟测试浏览器 → 按需装内核。
3. **内核安装策略**：`playwright install chromium`（约 440MB，一次下载永久复用）；仅无头批量截图可 `--only-shell`（约 280MB）；不需要本地抓取时跳过。
4. **装不上 / 公司网络受限 / 代理失败**：不折腾——直接落回通道②/③，任务流程不中断，交付说明标注所用通道。
5. setup 脚本只做"检查→安装→冒烟→验证"，不写死任何本地路径（内核由 Playwright 自动装到系统默认位置），保持技能可移植。

## 标准流程（observe-act-observe）

1. **确认目标**：URL 或站名；问清收集范围（最新季 only / 全系列 / 指定品类）与数量要求。
2. **打开页面（按所选通道）**：通道① `playwright-cli open <url>` → `playwright-cli goto <url>`（可加 `--headed` 供用户观察）；通道② 用 Agent 内置浏览器驱动导航（如豆包 `bu.navigate`）。
3. **定位内容**：`playwright-cli snapshot` 取元素 ref，找"秀场/时装秀/fashion show/系列"入口；点按后用新 snapshot 跟进。
4. **提取文字**：用 snapshot / `eval` 读取设计理念、系列说明等正文；关键表述保留原文并注明来源页。
5. **下载图片**：优先取页面 `<img>/<source srcset>` 中的高清直链（注意 `?wid=` 等缩放参数可调大分辨率），用本地下载保存；或 `playwright-cli screenshot` 截取渲染元素。
6. **落盘登记**：按下方"落盘规范"写入项目文件夹，生成 manifest。

## 落盘规范

> 命名与 manifest 字段规范遵循 fashion-studio 的 `asset-library-schema.md` 定义；未安装 fashion-studio 时按本表执行。

### 落盘位置：什么阶段搜集的素材，就落到对应阶段的参考图文件夹里

按照 fashion-studio 的项目文件夹结构，采集来的素材按用途分类放到对应阶段的"参考图"子文件夹：

| 素材内容 | 落盘位置 | 用途说明 |
|---|---|---|
| 灵感/氛围/情绪类参考图 | `01_前期企划板/灵感版/参考图/` | 作为灵感参考，发散设计思路 |
| 主题概念/文化/艺术参考 | `01_前期企划板/主题版/参考图/` | 可作为参考，也可以直接使用 |
| 色彩搭配/色板参考 | `01_前期企划板/色彩版/参考图/` | 作为色彩参考，提炼配色方案 |
| 面料肌理/材质参考 | `01_前期企划板/面料版/参考图/` | 作为面料参考，选择对应面料 |
| 纹样/印花/工艺参考 | `01_前期企划板/纹样工艺版/参考图/` | 作为工艺参考，选择对应工艺手法 |
| 廓形/服装版型参考 | `01_前期企划板/廓形版/参考图/` | 有要求时直接使用服装处理后放进去再做 |
| 服装设计/款式参考 | `02_设计效果图/参考图/` | 作为参考，也可以直接选好的部分结构调整后使用 |
| 配饰/鞋包/首饰参考 | `04_配饰版/参考图/` | 通常搜集到的直接使用 |
| 摄影大片/拍摄风格参考 | `05_摄影大片/参考图/` | 作为拍摄风格、构图、光线的参考 |
| 纯文字调研要点 | `01_前期企划板/调研板/` | 整理成设计调研要点文档，作为前期调研参考 |

### 命名与manifest规范

- 目录结构：每个阶段的参考图文件夹内，按采集来源建子文件夹（如 `LV_SS27_秀场/`）
- 图片命名：`<品牌>_<季>_<内容>_<序号>.jpg`（例：`LV_SS27_keylook_01.jpg`）；图片保持原比例，不缩放不加水印
- 文字类：`<品牌或主题>_<季>_调研要点.md`，内容含"整理要点 / 来源URL / 用途建议"
- 每批生成 `manifest.csv`（或 .md）字段：`文件名 | 来源URL | 拍摄/发布日 | 内容描述 | 版权分级 | 用途建议`
- 落盘根目录：当前对话绑定的项目文件夹（不写死绝对路径，保持技能可移植）

### 素材用途分级（按内容判断）
- **参考类**：只作为灵感、风格、手法参考，不直接使用
- **可直接使用类**：配饰、廓形参考等，经过处理后可以直接用到设计里
- **可改编使用类**：服装设计参考，可以选好的部分结构调整后直接使用

### 采集后的衔接流程
采集完素材并落盘后，直接进入 fashion-studio 的设计流程：
1. 如果是从零开始：从前期企划板开始，素材已经按用途分类放到对应文件夹
2. 如果已经做了一半：按 warm start 流程，从第一个没完成的阶段继续
3. 采集来的素材都是参考素材，最终设计要过版权分级（🟡素材终稿须实质转化）

## 版权分级（引用 fashion-studio 定义：参考全绿，交付分级）

> 本表为 fashion-studio `copyright-compliance.md` 版权分级（🟢/🟡/🔴/⚪）的摘要；详细判定与自查流程以该文件为准。**参考层一切图皆可参考无红线**；分级只作用于**交付**（参赛/商用/公开发布）。

| 分级 | 范围 | 可用性 |
|---|---|---|
| 🟢 | 自有产出/公共领域/已授权 | 参考与交付全可用（可作终稿锚点） |
| 🟡 | 当代品牌/在世设计师/高定的**整件或原创面料**（秀场图除外——全绿，见下） | **参考随便用**（垫图/发散/学手法）；交付：练习/内部全 🟢，**参赛/商用/公开发布须实质转化**（改动 ≥3 层） |
| 🔴 | 品牌 Logo、老花、注册印花、可识别商标 | **看与学无限制**（提炼配色/构图/手法）；**慎喂垫图**（模型会复现标志、难剥离）；**公开交付不复现** |

- 抓取的**秀场图默认 🟢 全绿**：参考层与过程全开（看/学/拆/垫、可作长期参考），不标 🟡；下载即登记，来源可溯。**拿秀场款当改造基底是行业常态**（改结构/换面料/调色彩/改款式即完成改造，非警戒线）；真正的红线只剩 🔴 老花/Logo（慎喂垫图、公开交付不复现）与真人面容（**可垫图，成片实质改到不可指认原真人即可用**——改五官/发型/妆容/年龄/气质等实质维度，非滤镜级微调）。
- 公开交付的成片不得含可识别的品牌标识；真人脸垫图成片须实质改到不可指认原真人（非滤镜级微调）。

## 失败与降级

- **反爬拦截**（页面返回 Access denied / 验证页）：换地区域名（如国际站被拦换中国官网）、换入口、必要时由用户在本地浏览器带登录态接管；**不硬绕验证码**。
- **登录墙/验证码**：检测到即停，请用户接管浏览器完成登录，或换可访问入口。
- **站内找不到目标季**：退回搜索该品牌该季新闻稿/官网杂志页，标注来源。
- **本地 CLI 不可用**：确认 `npx`/Node 存在；报错时读错误信息修复。若本地环境缺失但 Agent 内置浏览器自动化可用（如豆包 bu），切到通道②；两者皆无才走通道③手动放图，并在交付说明中标注所用通道与取舍。

## 验证

- 落盘后逐张用图片查看工具确认可读、内容正确（非错误页/占位图）。
- 核对 manifest 字段齐全、来源 URL 可访问。
- 与用户核对：数量、清晰度、命名是否符合预期。
